THE BUTTONS, NOT THE FORM

动的是按钮，不是下面那片表单。

19:07 你纠正得对：前面我把「类型切换」一路做成了内容区换页（H1 卷帘），整套理解偏了。卷帘已从项目代码里撤干净，录入页 5 处类型字段恢复瞬时 v-if 切换、零动效。这一轮只做三个类型按钮本身：点 MCU 时，选中态怎么从 Flash 按钮换到 MCU 按钮。

边界写死：按钮本体零位移、零缩放、零旋转；动的只是按钮里那层「选中态颜色」和至多一条线。信号黄只作「动作中的线」，不是常驻选中指示器（17:56 那条静态黄线已否）。下方内容区在舞台里故意画成灰化虚线框，标注「瞬时切换 / 零动效」——它不是动效对象。
⚠️ 本页未采用（2026-11-10 19:40）：用户看了 T1–T4 后又提出「让框灵活平移，颜色改变」，并从 S1–S4 中拍板 S1 整框平移 + 同步换色。方向没错，但这四个「按钮内部擦除交接」方案没有被选中，仅留作备选。项目里落地的是 S1：只有一个框在三个按钮上滑动，按钮与文字仍钉在原位。

舞台里直接点三个按钮，可反复 Flash ↔ MCU ↔ 其他；工具条能依次播放 T1–T4。

02

四个按钮切换样板 · 未采用 / 备选

点「试用」会切到该方案并自动演示一次 Flash → MCU；之后可以直接点舞台按钮反复看。四个方案都只动按钮里那层选中态，按钮本体钉在原位。

T1选中态擦除交接备选
旧擦出 + 新擦入 220ms · ease-in-out · 方向随切换方向
怎么动：旧按钮的选中色沿切换方向被擦掉，新按钮的选中色同步擦入，一条清晰的擦除边缘从旧按钮走向新按钮。最像「选中态从 Flash 换到 MCU」，有来路有回路，且按钮本身一个像素都不动。Flash→MCU 向右擦、MCU→Flash 向左擦。
T2一条线扫过按钮组
2px 线 200ms · ease-in-out · 扫到即落定
怎么动：切换瞬间一条 2px 信号黄竖线从旧按钮中心扫到新按钮中心，线到达时新按钮点亮、旧按钮熄灭。呼应你在危险弹窗挑的 F1 生长线——整排按钮里唯一在动的就是这条线，按钮与文字都不动。注意这是「一条线移动」，不是按钮位移。
T3只擦入（最轻）
新擦入 180ms · ease-out · 旧瞬时消失
怎么动：旧按钮选中色瞬时消失，新按钮选中色沿方向擦入。最短、最轻、绝不会有两块同时半透明叠着；代价是「换过去」的方向感比 T1 弱一些。适合觉得 T1 还是偏多的人。
T4交叉淡变 + 描边点亮下限对照
旧淡出 / 新淡入 160ms · 一次内描边
怎么动：旧选中色淡出、新选中色淡入，新按钮同时有一次极短的 1px 内描边点亮。纯颜色 / opacity，零裁切，最克制。提醒：你当初否掉弹窗「遮罩淡入」的理由是「跟没加没啥区别」，这版可能也偏弱，留作下限对照。
✕已否 / 仍然不做
内容区卷帘 · 静态黄色指示线 · 按钮位移缩放旋转 · stagger
内容区卷帘换页（H1）：19:07 已否，项目代码全量撤回。按钮底部 2px 信号黄线：17:56 已否。仍然禁止：按钮本体左右平移 / 缩放 / 旋转（会变成「乱飞」）、三个按钮逐个错峰点亮、装饰性循环、spring 回弹。特批例外：19:40 放行了「选中框」这一层 translateX 平移（S1），按钮本体依旧不许动，见 S 组样板 与规范修订 5。
03

备选方案 · 落地要点（当前未采用）

项目里三个按钮在 pages/chips/new.vue 的 <div class="flex gap-3"> 里，目前选中态靠 :class 切边框 / 底色 / 文字色，已有 transition-colors。落地只改这一处，内容区 5 处 v-if 一行都不碰。

<!-- 每个按钮加一层「选中态」，按钮本体不参与动画 -->
<button class="type-btn ..." :class="{ 'is-on': form.chip_type === 'flash' }"
        :aria-pressed="form.chip_type === 'flash'" @click="...">
  <span class="type-btn-sel" aria-hidden="true"></span>
  <span class="type-btn-lbl">▣ Flash 存储</span>
</button>

/* utilities.css · 以 T1 为例，只有这层在动 */
.type-btn { position:relative; overflow:hidden; isolation:isolate; }
.type-btn-sel { position:absolute; inset:0; z-index:1; pointer-events:none;
  clip-path:inset(0 0 0 100%); }
.type-btn.is-on .type-btn-sel { clip-path:inset(0 0 0 0); }
.type-btn-lbl { position:relative; z-index:2; }

.type-btn-sel.out-R { animation:wipeOutR 220ms var(--ease-emphasis) forwards; }
.type-btn-sel.in-R  { animation:wipeInR  220ms var(--ease-emphasis) forwards; }
/* direction 由 from/to 的按钮序号比较得出；动画结束把 is-on 落到新按钮 */
样板落地要点
T1需要一层 .type-btn-sel；切换时给旧 / 新两层分别挂 out / in 动画，方向由按钮序号比较；动画结束清 class、把 is-on 落到新按钮
T2按钮组容器 position:relative + 一条绝对定位的 .scan 线，用 translateX 从旧按钮中心扫到新按钮中心；无需选中态层动画
T3T1 的简化版：只给新按钮挂 in 动画，旧按钮直接移除 is-on；最省事
T4连 clip-path 都不用，只动 opacity + 一次内描边；注意可能被嫌「跟没加没啥区别」
三个坑：① 选中态层必须 pointer-events:none，否则挡住点击；② 动画用 forwards 只挂在「正在切换」的临时 class 上，播完立刻清掉，别让 clip-path 长期残留在选中按钮上；③ 快速连点要先清掉上一次动画、把 is-on 强制落定到当前值再启动新动画，否则会留下半截选中态。prefers-reduced-motion 下直接落定、不播动画。
验收口径：动效只出现在三个按钮上，下面表单切换是瞬时的；按钮本体无位移 / 缩放 / 旋转；字段值不丢；快速连点不留半截选中态；prefers-reduced-motion 下直接换到位。
