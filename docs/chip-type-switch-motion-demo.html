H1卷帘换页已否
旧 220ms · ease-in-out · 总 220ms
怎么动：新内容先在底下就位，旧内容从上往下被擦掉，一条清晰的分界线扫过去，扫过的地方从 Flash 变成 MCU。最像「换了一页」，也最干净——没有两块内容同时半透明叠着，没有空白帧，不位移。用户随后 19:07 否决整套卷帘方向，已撤回。
H2双向擦除
旧 / 新各 240ms · 新 @40ms · 总 280ms
怎么动：旧从上往下擦掉的同时，新也从上往下展开，两层像拉链咬合。比 H1 多一层「正在生成」的感觉，代价是中间有一小段两层内容同时可见，略糊。
H3收成一条线再展开最易落地
旧收 180ms → 新展 220ms@180ms · 总 400ms
怎么动：旧内容先向中间收成一条细线并淡出，新内容再从同一条线上下展开。呼应你在危险弹窗挑的 F1「点 → 线 → 窗」，形状生长的味道最足。有来路有回路，但中间有一瞬空白，总时长也最长。好处是旧新不同时存在，落地不用处理布局叠加。
H4横向换页
旧 / 新各 240ms · 新 @40ms · 总 280ms
怎么动：方向横过来：旧从左往右擦掉，新从左往右展开。和弹窗 F1 的横向生长线同源，读起来像「一行数据被刷成另一行」。注意这是遮罩擦除，不是内容左右滑动——内容始终钉在原位。

03

归档 · 当时的落地实现（已撤回）

归档原文：项目里 5 处类型字段分散在表单各处，曾被归并为 4 个 .type-slot 槽位：分类区 / JEDEC ID / Flash·MCU 自动读取面板合并成一格 / UID 长度+容量。每槽一层 <Transition name="type-swap">，由同一套 leave 规则驱动，四槽同时切换、不做错峰。互斥的两个读取面板共用同一格，让「Flash 切到 MCU」最显眼的那块真正叠放卷帘。

<!-- pages/chips/new.vue · 读取面板槽位（真实结构） -->
<div class="type-slot mt-3">
  <Transition name="type-swap">
    <div v-if="form.chip_type === 'mcu'" key="mcu" class="type-pane …">…MCU 面板…</div>
    <div v-else-if="form.chip_type === 'flash'" key="flash" class="type-pane …">…Flash 面板…</div>
  </Transition>
</div>

/* utilities.css · H1 落地规则 */
.type-slot { display:grid; align-items:start; }
.type-slot > * { grid-area:1 / 1; min-width:0; }
.type-slot:not(:has(> *)) { display:none; }   /* 空槽撤掉，防 space-y-5 留白 */

.type-swap-enter-active { z-index:0; }           /* 新块直接就位，不做任何动画 */
.type-swap-leave-active {
  z-index:1; pointer-events:none;
  animation:type-swap-wipe-out 220ms var(--ease-emphasis) forwards;
}
@keyframes type-swap-wipe-out {
  from { clip-path:inset(0 0 0 0); }
  to   { clip-path:inset(100% 0 0 0); }
}
要点为什么这么做
4 槽而非 5 槽Flash / MCU 自动读取面板互斥且紧邻，合并进同一格才能真正「旧擦掉露出新」；分成两槽会变成一上一下两块各自擦，不像换页
grid-area:1/1旧新叠同格，容器高度取 max(两者)，切换期间不塌不跳；align-items:start 防止矮块被拉成另一块的高度
:not(:has(> *))不能用 :empty——Vue 的 v-if=false 会留 <!----> 注释节点。空槽 display:none，space-y-5 算给它的 20px margin 就不渲染
:key="form.chip_type"JEDEC / UID 长度两处的 v-if="!== 'other'" 在 Flash↔MCU 下恒为 true，不加 key Vue 只更新文本、不触发过渡
forwards 只在 leaveleave 元素播完即被 Vue 移除；enter 侧不写任何 animation / clip-path，所以不会残留裁剪裁掉 UInputMenu 下拉浮层
为什么不用 G1 那套常驻 DOM + grid 0fr→1fr：录入表单外层是 space-y-5，Tailwind 会给「除第一个外的所有子元素」加 20px 上间距，收起的高度 0 容器仍会被算进去 → 折叠态留白、几个空容器还会累加；5 处读取器面板常驻也会带来额外组件生命周期与 inert 负担。H1 用 常驻槽位 + 内部 v-if：槽位在、面板不常驻，再用 :not(:has(> *)) 把空槽从布局里彻底撤掉，避开了留白又拿到叠放能力。切换语义也和「展开 / 收起」不同，硬套 G1 会别扭。
验收口径（本地 Nuxt dev / HMR 核对）：关掉动效仍能正常切换类型、字段值不丢（v-model 绑在 form 上，DOM 重建不影响）；UInputMenu 下拉浮层不被裁切；快速连点三个按钮不能留下半截内容或叠两块；切到「其他」时 4 槽应干净收起、不留空白行；prefers-reduced-motion 下直接换到位。
