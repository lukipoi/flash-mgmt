读取报错的 toast，得重新设计一张。

现在的太丑，问题不在颜色深浅，在它根本不是这套界面的东西：Nuxt UI 默认是消费级卡片——圆角、24px 大投影、双层 ring，浮在页面上像广告弹窗；而项目是直角、1px 描边、零偏移阴影的工业控制台。加上读取失败的文本是「长错误摘要 + 排查建议」硬塞进一行 text-sm，技术信息不用等宽，成功/警告/失败只靠颜色区分，还全是 timeout: 0 常驻，右下角越堆越乱。

不是补个 CSS 能解决的。规范页 04 章那张 .toast 基准件只有一行 OK 示例，没有 error 变体、没有长文本排版、没有堆叠规则。所以这一页是四个重新设计的形态，不是把默认卡片换个圆角。21:13 已拍板 R1 / R4 分流并落地到项目，下面四个卡片保留作设计记录。
两条规范边界我先守住：① hazard 红黑滚动条按 07 章只用于危险操作区 / 不可撤销确认 / 设备运行中，且每屏最多 1 处；读取失败是故障回执、还会堆叠，所以四版都不加循环动画（R4 是静止斜纹，不占例外名额）。② 信号黄只做「排查 / 下一步」这个行动线索的小方块，不拿来做错误色；错误一律 --ef-danger。入场统一 150ms 纯 opacity，无位移 / 缩放 / spring。
✅ 21:13 已定案并落地：「R4 只留给所有 ERR 和 WARN，别的走 R1」。color:'error' / 'warning' → R4 静止警戒带；'success' / 'info' / 'neutral' → R1 结构化回执。落在 app.config.ts 的 ui.toast + utilities.css 的 .ef-toast，26 处调用一行没改。点「按定案分流演示」看五种状态的实际组合。
01

现状 · 丑在哪

左边是照 Nuxt UI 默认 ui.toast.slots.root 还原的当前 toast（rounded-lg shadow-lg ring ring-default p-4），右边是具体问题。

STC 读取失败
串口打开失败: Access is denied（确认芯片已断电重新上电、串口未被占用）
×
  • 圆角 + 24px 大投影 + ring：三种「浮起来」的语汇叠在一起，跟零偏移阴影、1px 描边的基准件直接冲突。全站直角化只归零了圆角，投影和 ring 还在。
  • 长文本挤成一行：错误摘要和排查建议用全角括号糊在一起，text-sm 换行后没有层级，扫一眼找不到「我该干什么」。
  • 技术信息不用等宽：端口、ChipID、UID、协议版本都是数据，混在正文字体里看不出是数据。
  • 只靠颜色区分状态：成功 / 警告 / 失败没有状态标识，色弱或明暗切换后更难分辨。
  • timeout: 0 常驻：录入库 13 个通道 + 识别页 13 个通道全都不自动消失；useToast() 内部 maxToasts = 5 会挤掉最旧的，所以是「最多 5 条常驻」而非无限堆叠 —— 但一摞 5 张消费级卡片依然很吵。

6px 静止红黑斜纹 · 不滚动

四版都是直角、1px 描边、零偏移阴影、无位移；入场只有 150ms 纯透明度。R1 / R3 会把描述拆成「摘要 / 排查」两段，R2 / R4 保持单块描述。

03

落地方式（已落地）

不用改 26 处 toast.add() 也能换外观：Nuxt UI 的 useToast() 会把 appConfig.ui.toast 合并进组件的 tv 主题，注入自定义类即可；状态码用 CSS 伪元素按 variants.color 的类名生成。

// app.config.ts —— 保留默认布局类 + 追加 ef-toast-*，按状态分流
toast: {
  slots: {
    // ⚠️ appConfig.ui.toast.slots 是「替换」theme.slots，不是合并；只写自定义类会丢布局
    root: 'relative group overflow-hidden bg-default shadow-lg rounded-lg ring ring-default p-4 flex gap-2.5 focus:outline-none ef-toast',
    wrapper: 'w-0 flex-1 flex flex-col ef-toast-wrap',
    title: 'text-sm font-medium text-highlighted ef-toast-title',
    description: 'text-sm text-muted ef-toast-desc',
    icon: 'shrink-0 size-5 ef-toast-icon',
    close: 'p-0 ef-toast-close',
    progress: 'absolute inset-x-0 bottom-0 ef-toast-progress'
  },
  variants: {
    color: {
      error:     { root: 'ef-toast--band ef-toast--err'  },  // → R4
      warning:   { root: 'ef-toast--band ef-toast--warn' },  // → R4
      success:   { root: 'ef-toast--ok'      },              // → R1
      info:      { root: 'ef-toast--info'    },              // → R1
      neutral:   { root: 'ef-toast--neutral' },              // → R1
      primary:   { root: 'ef-toast--info' },
      secondary: { root: 'ef-toast--neutral' }
    }
  }
}

/* utilities.css —— .ef-toast 基类就是 R1，--band 覆盖成 R4 */
.ef-toast {
  --ts: var(--ef-line-strong);
  border: 1px solid var(--ef-line-strong); border-left: 3px solid var(--ts);
  border-radius: 0; background: var(--ef-surface-raised); box-shadow: none;
  /* 逐项盖掉默认 root 的 bg-default / shadow-lg / ring / rounded-lg / p-4 / gap-2.5 */
  /* ⚠️ 不写 position：交给 Toaster 的 absolute inset-x-0，改回 relative 会裁掉描述 */
}
.ef-toast--err  { --ts: var(--ef-danger);  }
.ef-toast--warn { --ts: var(--ef-warning); }
.ef-toast--ok   { --ts: var(--ef-success); }
.ef-toast--info { --ts: var(--ef-info);    }

/* R1：等宽状态码 + description 做成深底等宽日志块 */
.ef-toast::before { content: 'OK'; /* 按 --ok / --info / --neutral 切换 */ }
.ef-toast-desc    { background: var(--ef-surface-sunken); border: 1px solid var(--ef-line);
                    font-family: var(--font-mono); white-space: pre-line; }

/* R4：顶部 6px 静止斜纹带 + 状态色描边；刻意无 animation */
.ef-toast--band::before {
  height: 6px;
  background: repeating-linear-gradient(-45deg, var(--ts) 0 8px,
              var(--ef-surface-sunken) 8px 16px);
}
.ef-toast--band .ef-toast-title::before { content: 'ERR · '; }
.ef-toast--warn.ef-toast--band .ef-toast-title::before { content: 'WARN · '; }

/* 入场只有 150ms 纯 opacity */
.ef-toast { animation: ef-toast-in 150ms ease-out both; }
三个必须注意的点：① tv(theme) 的默认 root 仍会带 shadow-lg / ring / rounded-lg / p-4，所以 CSS 里要把这些属性逐项写全，不能只写新增的；② 状态码靠 ::before 生成，调用处零改动；但 UToast 的 DOM 固定（没有独立的抬头 / 日志块 / 排查行槽），所以 R1 落地时用 root::before 做等宽状态码、description 做成深底等宽日志块、::after 做右上角切角三角 —— 设计稿里「排查 ·」信号黄小方块因此没落地（纯 CSS 判断不出 description 是否含排查建议，乱加会误导）；③ timeout: 0 常驻 + maxToasts = 5，最多同时 5 条，建议后续做「同通道重复失败只留最新一条」；④ 布局契约（21:40 截图后修复）：slots 是替换不是合并，必须保留默认布局类；.ef-toast 绝不能写 position: relative —— 它会盖掉 Toaster 的 absolute inset-x-0，让 ToastRoot 掉进 viewport 的 data-[expanded=true]:h-(--height) 固定高度 flex 流，被压到 40–56px，overflow:hidden 把 description 整块裁没，只剩一条窄横幅。修复后实测 position:absolute / width:384px / height:96px，描述完整可见。
不改的东西：hazard 红黑滚动条（07 章：仅危险操作区、每屏 1 处、唯一常驻循环例外）；按钮 / 卡片位移；spring 回弹；发光；图标旋转。四版入场都只有 150ms opacity，prefers-reduced-motion 下由 theme.css 全局兜底直接到位。

选型对照

R1 · 故障回执★★★ 抬头 / 日志块 / 排查三段★★ 三条约占 260px需拆 description推荐：长错误信息最有层次，「下一步」最清楚。卡片偏高，堆叠要配去重。
R2 · 大状态码★★ 标题 + 一行描述★★★ 最矮、最不吵零改动最稳妥、最快落地；但「排查建议」仍和摘要挤在一行，长文本优势没吃到。
R3 · 终端日志★★★ 多行、前缀分层★ 黑底块最抢眼需拆 description和实时日志框同语汇，开发者视角最顺；中文等宽偏密，多条同时出现会压过页面。
R4 · 静止警戒带★★ 抬头 + 描述 + 排查★ 斜纹多条会吵零改动分量最重，适合「不可恢复失败」单条专用；若所有读取失败都用它，会稀释 hazard 母题。

最终定案（21:13）：ERR / WARN 走 R4，OK / INFO / NOTE 走 R1，已落地（见 03 章）。R2 / R3 留作备选，未采用。
