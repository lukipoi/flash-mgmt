ONE FRAME, MOVING ACROSS THE BUTTONS

一个框滑过去，颜色跟着换。

你这句「让框灵活平移，颜色改变」，我按三个类型按钮上那个选中框来理解 —— 不是每个按钮各自擦除（那是 T1–T4），而是只有一个框，从 Flash 滑到 MCU 时会经过中间位置，滑到哪就点亮哪，同时从数据蓝渐变成专用紫。19:40 你拍板「S1，这样才符合我胃口」，已按这一版落地到项目代码。

✅ 已拍板（19:40 选 S1）：规范 06 章写的是「按钮本体零位移 / 零缩放 / 零旋转」，你最早也说「不想按钮乱飞」。这一版只放行「选中框」这一层平移，三个按钮和它们的文字仍然一个像素都不动，框必须 pointer-events:none。默认缓动是克制的 cubic-bezier(.4,0,.2,1)；「轻微过冲」我做成可选项给你试，不做 spring 回弹——过冲一大就真的会变成乱飞。它已是继 hazard 滚动条、F1 弹窗生长、G1 箭头旋转之后的第 4 个特批例外，严格限定在框上，已同步写入 规范 06 / 07 章修订 5。

点舞台里三个按钮可反复看；工具条能调时长 / 缓动 / 配色，并依次播放 S1–S4。特意留了「切到其他」，能看到框一步跨过 MCU 的长距离平移。

02

四个「框平移」样板 · S1 已落地

19:40 已拍板 S1，项目里落地的就是它；S2–S4 留作备选与对照。点「试用」会切到该方案并自动演示一次 Flash → MCU，之后可直接点舞台按钮反复看。四个方案里按钮本体都不动，区别在框怎么滑、颜色什么时候换。

S1整框平移 + 同步换色已落地
位置 + 颜色 260ms · ease-in-out · 同时过渡
怎么动：框从旧按钮滑到新按钮，位置与颜色同时过渡——移动途中蓝色渐渐化开成紫色，落定时刚好是目标色。从 Flash 直接切「其他」时框会经过 MCU，能清楚看到一个实体在整排上移动，这是「灵活」最直观的一版。
S2平移带轻微伸缩最灵活
S1 + 内层 scaleX 1→1.055→1 · 320ms 建议
怎么动：在 S1 基础上，框沿前进方向轻微拉长再收回，像被拽过去一样，手感最活。过冲只有 5.5% 且单次收回，不是 spring 回弹。拉伸只作用在框的内层，不碰位移用的 transform，两套动画互不干扰。代价是比 S1 多一层 DOM。
S3变色先行，再平移
原地换色 80ms → 平移 220ms · 顺序交代
怎么动：框先在原地变成目标色，停一拍，再滑过去。看起来像「先确认要去哪儿，再动」，最有交代感；缺点是总时长最长，快速连点时两段时序容易打架，需要严格 cleanup。
S4只平移、不换色下限对照
框固定中性色 · 仅 transform 过渡
怎么动：框保持中性描边，只有位置变。用来回答「颜色改变到底有没有必要」——当时用来判断换色是否必要；项目里三个按钮本来就按类型分色，所以 S1 直接复用了现有配色，没有引入新颜色。
✕仍然不做
按钮本体位移 · spring 回弹 · 内容区动效 · stagger
框可以滑，按钮不可以。三个按钮连同文字必须钉在原位；不做弹性回弹、不做逐个错峰点亮、不做装饰性循环。内容区卷帘换页（H1）已全量撤回，下方 5 处 v-if 保持瞬时切换、零动效。
03

S1 · 已落地实现记录

已改两个文件：pages/chips/new.vue 的 <div class="flex gap-3"> 三个按钮 + 定位 JS、assets/css/endfield/utilities.css 的 .type-frame 一套规则；内容区 5 处 v-if 一行都没碰。⚠️ 口径更正：项目里三个按钮本来就按类型分色（flash border-data-500 / bg-action/10 / text-action、mcu border-special-500 / bg-special-500/10 / text-region、other 中性），不是统一行动色 —— 所以 S1 直接复用这三套色，没有引入新颜色。落地时把按钮本体改成恒定 border-line bg-surface-muted，选中视觉全部交给框，按钮只保留文字色。

<!-- pages/chips/new.vue · 三个按钮 + 唯一一个框 -->
<div ref="typeTabs" class="type-tabs flex gap-3" :data-current="form.chip_type">
  <button type="button" data-type="flash"
          class="type-btn ... border border-line bg-surface-muted"
          :class="form.chip_type === 'flash' ? 'text-action' : 'text-ink-secondary hover:text-ink'"
          :aria-pressed="form.chip_type === 'flash'" @click="form.chip_type = 'flash'">
    <span class="type-btn-lbl">▣ Flash 存储</span>
  </button>
  <!-- mcu / other 同构 -->
  <span ref="typeFrame" class="type-frame" aria-hidden="true">
    <span class="type-frame-inner" :class="form.chip_type === 'flash'
      ? 'border-data-500 bg-action/10'
      : form.chip_type === 'mcu' ? 'border-special-500 bg-special-500/10'
      : 'border-ink-tertiary bg-surface-muted/10'"></span>
  </span>
</div>

/* assets/css/endfield/utilities.css · 框是唯一会动的层 */
.type-tabs { position:relative; --type-dur:260ms; --type-ease:cubic-bezier(.4,0,.2,1); }
.type-btn { position:relative; }
.type-btn-lbl { position:relative; z-index:3; pointer-events:none; }
.type-frame { position:absolute; top:0; bottom:0; left:0; z-index:2; pointer-events:none;
  width:var(--fw,0px); transform:translateX(var(--fx,0px));
  transition:transform var(--type-dur) var(--type-ease), width var(--type-dur) var(--type-ease); }
.type-frame-inner { position:absolute; inset:0; border-width:1px; border-style:solid;
  transition:background-color var(--type-dur) var(--type-ease),
             border-color var(--type-dur) var(--type-ease); }
.type-frame.no-trans, .type-frame.no-trans .type-frame-inner { transition:none; }
/* 颜色不写死：由模板的 Tailwind 类提供，明暗主题自动跟随 */

/* new.vue · JS 只测尺寸，不逐帧驱动动画 */
function placeTypeFrame(instant = false) {
  const wrap = typeTabs.value, frame = typeFrame.value;
  if (!wrap || !frame) return;
  const btn = wrap.querySelector(`.type-btn[data-type="${form.chip_type}"]`);
  if (!btn) return;
  const r = btn.getBoundingClientRect(), w = wrap.getBoundingClientRect();
  if (instant) frame.classList.add('no-trans');
  frame.style.setProperty('--fx', `${r.left - w.left}px`);
  frame.style.setProperty('--fw', `${r.width}px`);
  if (instant) { void frame.offsetWidth; frame.classList.remove('no-trans'); }
}
watch(() => form.chip_type, () => placeTypeFrame());
onMounted(() => {
  nextTick(() => placeTypeFrame(true));
  frameObserver = new ResizeObserver(() => placeTypeFrame(true));
  if (typeTabs.value) frameObserver.observe(typeTabs.value);
});
onUnmounted(() => frameObserver?.disconnect());
样板落地要点
S1 · 已落地transform / width / background-color / border-color 全部走 CSS transition，JS 只测尺寸改变量、不逐帧；框色复用三个按钮原有的 Tailwind 类
S2再加一个内层 .type-frame-inner，切换时挂一次 scaleX 关键帧，动画名与位移的 transition 分属两层，不冲突；transform-origin 按方向设 left / right
S3把「改 data-current」和「改 --fx」拆成两步，中间隔 80ms；快速连点必须先清掉未执行的 timeout，否则框会朝旧目标跑
S4未采用。若要「只平移不换色」，把 .type-frame-inner 的 :class 固定成一套中性色即可；项目现有配色本就按类型分好，S1 复用它没有额外成本
五个坑：① 框必须 pointer-events:none，否则挡住点击；② 文字层 z-index:3 要压过框的 z-index:2，否则会被半透明底色染掉；③ 位置用 getBoundingClientRect() 实测，窗口变化或侧栏展开会改变按钮宽度，需 ResizeObserver 重算并临时关掉 transition，否则框会「自己滑一下」；④ 位移用 transition 而不是 animation + forwards，快速连点天然从当前位置继续、不留半截框（这正是 T 组踩过的坑）；⑤ prefers-reduced-motion 下 transition:none 直接落定。颜色变量变化会触发普通属性的计算值过渡，不用 @property 注册。
验收口径：只有框在移动，按钮本体与文字零位移 / 零缩放 / 零旋转；下方表单瞬时切换；Flash → 其他 时框确实跨过中间按钮；字段值不丢；快速连点不留残影；明暗两套主题下框颜色都有对比度；prefers-reduced-motion 直接换到位。
